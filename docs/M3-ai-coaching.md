## การป้องกันคุณภาพ (RK7, RK8)

| ปัญหาที่พบจริงในการทดลองรอบแรก | การป้องกัน |
| --- | --- |
| ส่วน thinking ทำให้ตอบช้า ~70 วิ | `reasoning_effort: none` (ทดสอบแล้ว `think: false` ใช้ไม่ได้กับ endpoint `/v1`) + ตัด `<think>` |
| ปัดเศษ "7 ชั่วโมงครึ่ง" แทน 7 ชม. 22 นาที | prompt ให้คัดลอกตัวเลขพร้อมหน่วย + โค้ดปฏิเสธสรุปที่มีตัวเลขซึ่งไม่อยู่ในข้อเท็จจริง |
| อักษรรัสเซียหลุดมา ("сидนิ่ง") | โค้ดปฏิเสธอักษรที่ไม่ใช่ไทย/ละติน |
| แต่งเกณฑ์ "10,000 ก้าว", "นั่งไม่เกิน 8–9 ชม." | prompt ห้ามอ้างเกณฑ์ที่ไม่มีในข้อเท็จจริง อ้างได้เฉพาะ WHO |
| บอกว่า "HRV อยู่ในเกณฑ์ปกติ" เอง | prompt ห้ามตีความค่าร่างกายนอกรายการจากกฎ (FR17) |
| ชื่อ field หลุดมา | prompt + โค้ดปฏิเสธข้อความที่มี `_` |

ไม่ผ่านการตรวจ → ขอใหม่ 1 ครั้ง → ยังไม่ผ่านหรือ Ollama ไม่ทำงาน → ส่งรายงาน template พร้อมหมายเหตุ (D5)

## ผลทดลองหลังปรับ (9 รอบ)

- ข้อมูลจริงวันที่ 12 ต.ค. 3 รอบ และข้อมูลจำลอง 60 วัน 3 รอบ: ตัวเลขถูกทุกตัว ไม่มีอักษรแปลก ไม่มีเกณฑ์ที่แต่งขึ้น
- ใช้เวลา 11–29 วินาทีต่อรายงาน
- ปิด Ollama: ได้รายงาน template + หมายเหตุ ภายใน 1 วินาที

## สิ่งที่ต้องตัดสินที่ Gate M3

1. คุณภาพคำแนะนำยอมรับได้หรือไม่ (ทดลองรับจริงทาง LINE สัก 2–3 วัน)
2. คำลงท้าย: AI ใช้ "ครับ" บางครั้ง ต้องการ "ครับ" "ค่ะ" หรือไม่ใช้คำลงท้าย
3. ข้อสังเกตที่ยังเหลือ: บางครั้ง AI ยังตีความอุณหภูมิผิวหนังเล็กน้อย ("อาจเป็นสัญญาณให้สังเกต") จะเก็บตัวอย่างใน M4 แล้วปรับ prompt
