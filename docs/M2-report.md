# M2 — รายงานแรกทาง LINE: สรุปเพื่อรีวิวที่ Gate

ฉบับวันที่ 13 ตุลาคม 2026 · Product Owner อนุมัติให้พัฒนา M2 คู่ขนานกับการเทียบข้อมูลของ Gate M1

Features: F6 Completeness · F7 Metrics Engine · F8 Anomaly Rules · F10 Report Composer (template) · F12 Orchestrator

## วิธีใช้

```bash
./bin/fitbot run                     # ทุกเช้าหลังเปิดแอปให้ sync: ดึงข้อมูล → ตรวจความครบ → ส่งตามกฎ 5 ข้อ
./bin/fitbot run --dry-run           # ดูข้อความที่จะส่ง โดยไม่ส่งและไม่บันทึกสถานะ
./bin/fitbot report preview --user 1 # ดูรายงานจากข้อมูลในฐานข้อมูล
```

`run` แทน `collect` ได้เลย (ดึงข้อมูลให้ในตัว) ถ้ายังไม่อยากรับรายงานทาง LINE ระหว่างเทียบข้อมูล M1 ให้ใช้ `collect` ต่อไป

ดูรายงานที่มีข้อมูลหลายวัน (ข้อมูลจำลอง แยกฐานข้อมูล):

```bash
createdb fitbot_dev
FITBOT_DATABASE_URL='postgres:///fitbot_dev?host=/tmp' ./bin/fitbot migrate up
FITBOT_DATABASE_URL='postgres:///fitbot_dev?host=/tmp' ./bin/fitbot user add --name ทดลอง
FITBOT_DATABASE_URL='postgres:///fitbot_dev?host=/tmp' ./bin/fitbot dev seed --user 1 --days 60
FITBOT_DATABASE_URL='postgres:///fitbot_dev?host=/tmp' ./bin/fitbot report preview --user 1
```

## การตัดสินใจระหว่างพัฒนา (เสนอให้ PO ยืนยันที่ Gate)

| เรื่อง | สิ่งที่ทำ | เหตุผล |
| --- | --- | --- |
| ค่าตั้งต้น 3 / 14 / 14 วัน (Q12–Q14) | ค่าเฉลี่ยต้องมีข้อมูล ≥ 3 วัน, แนวโน้มต้องมี ≥ 14 วันใน 30 วัน, กฎค่าส่วนตัวเริ่มเมื่อ baseline ≥ 14 วัน | ตีความจาก Decision Log ปรับได้ใน `config.yaml` |
| แนวโน้ม | เทียบค่าเฉลี่ย 7 วันล่าสุดกับ 23 วันก่อนหน้า เปลี่ยน ≥ 5% ถือว่าเพิ่ม/ลด | เรียบง่าย ตรวจสอบได้ |
| เป้าหมาย WHO | นาทีออกกำลังกาย = fat burn + 2 × (cardio + peak) | WHO นับกิจกรรมหนัก 1 นาทีเท่ากับปานกลาง 2 นาที ต่างจากตัวเลข AZM ในแอปที่ไม่คูณ (เช่น AZM 48 นาที นับแบบ WHO ได้ 68 นาที) |
| ไม่รู้เวลาสวมใส่ | ถือว่าข้อมูลกิจกรรมไม่ครบ | ยืนยันไม่ได้ว่าสวมพอ (FR25) |
| ส่วนเทียบค่าเฉลี่ย | แสดง 7 ตัวชี้วัดหลัก ไม่แสดงทุกตัว | คุมความยาวรายงาน (~2,000 ตัวอักษรเมื่อมีข้อมูลครบ) |
| แหล่งอ้างอิงเกณฑ์ | ยืนยันแล้ว: AHA 60–100 bpm, bradycardia < 60 (ใช้ 40 ตาม Plan เพราะคนออกกำลังกายสม่ำเสมออาจต่ำถึง ~40), WHO SpO2 < 90% | ตาม Plan ที่ให้ยืนยันก่อน implement F8 |

## Acceptance Criteria และ test

| Feature | AC | ตรวจด้วย |
| --- | --- | --- |
| F6 | ครบ = สวม ≥ 50% และมีการนอนหลัก; ระบุได้ว่าขาดส่วนใด | `completeness_test` |
| F7 | ข้ามวันที่ไม่มีข้อมูล, มีจำนวนวัน, อ่าน ≤ 90 วัน, ไม่คำนวณแนวโน้มเมื่อข้อมูลน้อย, ผลคงที่ | `metrics_test` (ข้อมูลจำลองที่มีวันไม่มีข้อมูล) |
| F8 | กฎในไฟล์ตั้งค่า (`internal/anomaly/rules.yaml`), กฎค่าส่วนตัวเริ่มที่ 14 วัน, ทุกการเตือนบอกค่า เกณฑ์ แหล่งอ้างอิง | `anomaly_test` |
| F10 | ตัวเลขตรงกับ Metrics Engine, section เฝ้าระวังแสดงเมื่อมีเท่านั้นพร้อม disclaimer, "ไม่มีข้อมูล" แทน 0, รายงานบางส่วนบอกว่าไม่ครบ, ยาวเกินแบ่งข้อความ | `report_test` |
| F12 | กฎ 5 ข้อครบ, รายงาน ≤ 1 ฉบับ/วัน, ข้อความ sync ≤ 1 ครั้ง, lock กันรันซ้อน, แสดงเวลาที่ควรรันใหม่ | `orchestrator_test` (เวลาจำลอง: รันก่อน sync → รันซ้ำทันที → หลัง 2 ชม. → รันอีก), `collector_test` (lock) |

## สิ่งที่ต้องตัดสินที่ Gate M2

1. **OQ9** ความยาวรายงานและการใช้อีโมจิ (ตอนนี้ไม่ใช้อีโมจิ ยกเว้น ⚠ ในรายงานบางส่วน)
2. ยืนยันการตัดสินใจในตารางด้านบน โดยเฉพาะการคิดนาทีออกกำลังกายแบบ WHO
3. ทดลองจริงตาม Plan: รันก่อน sync, รันซ้ำทันที, รันหลัง 2 ชม. แล้วรีวิวข้อความบน LINE
