# Dashboard API (fitbot-web ระยะ 1)

`fitbot serve` เปิด HTTP API ให้ [fitbot-web](https://github.com/psupsri/fitbot-web)

- **ยังไม่มีระบบล็อกอิน** จึงยอมฟังเฉพาะ `127.0.0.1` หรือ `localhost` (ค่าเริ่มต้น `127.0.0.1:8787`) ถ้าระบุที่อยู่อื่นจะไม่ยอมเริ่ม
- การอ่านข้อมูลไม่เรียก LLM และไม่ส่ง LINE ตัวเลขทุกตัวมาจาก Metrics Engine และกฎค่าผิดปกติชุดเดียวกับรายงาน
- คำสั่งเดียวที่เปลี่ยนสถานะคือ `send-report` ซึ่งเรียก Orchestrator ตัวเดียวกับ `fitbot run` (ส่ง LINE จริง)
- guard กันเว็บอื่นในเบราว์เซอร์: Host และ Origin ต้องเป็น loopback และคำขอ POST ต้องเป็น `application/json`
- `--web DIR` เสิร์ฟหน้าเว็บที่ build แล้วจากโฟลเดอร์นั้นที่ `/`

## Endpoints

| Method | Path | ผลลัพธ์ |
| --- | --- | --- |
| GET | `/api/users` | ผู้ใช้ที่เปิดใช้งาน `[{id, name, timezone}]` |
| GET | `/api/users/{id}/dashboard?date=YYYY-MM-DD&days=N` | ข้อมูลทั้งหน้าของวัน D |
| POST | `/api/users/{id}/send-report` body `{"date": "YYYY-MM-DD", "partial": false}` | สั่งส่งรายงานของวัน D คืนผลของ Orchestrator |

### send-report

ทำงานแบบเดียวกับรอบอัตโนมัติ: ดึงข้อมูลล่าสุด ตรวจความครบ แล้วตัดสินตามกฎ 5 ข้อ

| สถานการณ์ | `partial: false` | `partial: true` |
| --- | --- | --- |
| ส่งแล้ว | `skip` ไม่ส่งซ้ำ | `skip` ไม่ส่งซ้ำ |
| ข้อมูลครบ | `full_report` | `full_report` |
| ไม่ครบ ยังไม่เคยแจ้ง | `sync_notice` ส่งข้อความให้ sync | `partial_report` ส่งรายงานบางส่วนทันที |
| ไม่ครบ แจ้งแล้วไม่ถึง 2 ชม. | `wait` | `partial_report` |
| ไม่ครบ แจ้งแล้วครบ 2 ชม. | `partial_report` | `partial_report` |

ส่งได้เฉพาะวันที่ผ่านมาแล้ว · ใช้ lock เดียวกับ launchd ถ้ารอบอัตโนมัติกำลังทำงานจะได้ 409 · การส่ง LINE ไม่ถูกตัดกลางทางเมื่อปิดหน้าเว็บ

`date` ไม่ระบุ = วันล่าสุดที่มีข้อมูล · `days` = จำนวนวันของกราฟ (1–90 ค่าเริ่มต้น 30)

### ฟิลด์ของ dashboard

| ฟิลด์ | เนื้อหา |
| --- | --- |
| `user`, `date`, `first_date`, `last_date` | ผู้ใช้ วันที่แสดง และช่วงวันที่มีข้อมูล (ใช้เลื่อนวัน) |
| `status` | ความครบของวัน D (`null` = ยังไม่เคยตรวจ) |
| `sleep` | การนอนหลักคืนวัน D: เวลาเข้านอน/ตื่น (HH:MM ตาม timezone ผู้ใช้) และนาทีแต่ละช่วง (`null` = ไม่มีการนอนหลัก) |
| `metrics[]` | ทุกตัวชี้วัด: ค่าวัน D, `text` ที่จัดรูปแบบเหมือนรายงาน LINE, ค่าเฉลี่ย 7/30/60/90 วันพร้อมจำนวนวันที่มีข้อมูล, แนวโน้ม |
| `weekly` | ออกกำลังกาย 7 วันเทียบเป้าหมาย WHO |
| `alerts.watch[]`, `alerts.improve[]` | ค่าที่ควรเฝ้าระวังและสิ่งที่ควรปรับปรุง (ตัดสินด้วยกฎ) |
| `report` | สถานะรายงานของวัน D, `coaching` (บทวิเคราะห์จาก AI แยกส่วน) และ `content` (ข้อความที่ส่งทาง LINE) |
| `series[]` | ค่ารายวันของทุกตัวชี้วัดย้อนหลัง `days` วัน ใช้กฎเดียวกับค่าเฉลี่ย: วันที่สวมไม่ถึงครึ่งวัน ค่ากิจกรรมเป็น `null` |

ค่าที่ไม่มีเป็น `null` เสมอ ห้ามแสดงเป็น 0 (FR4)
